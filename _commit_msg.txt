2.1-codegen: kill LocalCode silent template fallback + flip default to Enigma

Engine choice rationale: unlike imagegen/threed/videogen/audiogen (which
bridge external HF models because Enigma is not yet trained on those
modalities), code generation is Enigma's PRIMARY skill per the project
goals ('locally-trained AI capable of code & software development'). The
correct local engine here is the in-tree Enigma model itself, NOT an
external model like Qwen2.5-Coder-7B, DeepSeek-Coder-V2-Lite,
StarCoder2-7B, or CodeLlama-7B - those are finished products we would
delegate to, while Enigma is the trainable model we are building toward.

The pre-slice LocalCode already wired the Enigma path correctly via
ModelRegistry + EnigmaEngine, but masked load failures with a silent
TemplateCode fallback (self._fallback) - same anti-pattern killed in
the previous four 2.1 slices. A user who pointed CodeGen at a missing
or untrained model would silently receive keyword-template output that
looked like Enigma generations.

Changes:
- LocalCode: killed self._fallback = TemplateCode(); split load() into
  ImportError branch (logger.error + return False, hint --provider template)
  and Exception branch (logger.error naming the failing model + return False).
  unload() no longer references _fallback. generate() early-returns
  'Local Enigma provider not loaded' when engine is None.
- CodeGen.__init__ default_provider: 'template' -> 'local' with slice-stamp.
- argparse --provider default: 'template' -> 'local' with help text
  documenting both options ('local=Enigma model, template=offline keyword
  templates').
- Header docstring rewritten to name the engine and explain why Enigma
  (not an external model) is the right local choice.
- mod.json description updated to reflect new default and opt-in semantics.

Tests: TestCodeGenServiceDefaults (4 tests, all behavioural):
- test_default_provider_is_local
- test_local_has_no_silent_template_fallback (hasattr discriminator)
- test_load_failure_does_not_silently_fallback (lambda: False -> surfaced
  error mentioning local/enigma/load)
- test_local_uses_enigma_not_template (file-level source gate: '_fallback'
  not in LocalCode body, 'self.engine.generate' is in LocalCode body)

Note: inspect.getsource fails for modules loaded via
spec_from_file_location ('built-in class' TypeError). Read the mod source
directly via Path.read_text and slice the LocalCode class body by
'class LocalCode:' / '\nclass ' markers - same pattern other mod-loading
tests should follow for source-level gates.
