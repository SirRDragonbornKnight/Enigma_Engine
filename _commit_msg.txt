2.1-audiogen: swap pyttsx3-as-LocalTTS for Kokoro-82M + flip default

Engine comparison for local TTS at 16GB VRAM budget:
- Kokoro-82M (Apache 2.0, 82M, ~300MB) - top open TTS leaderboard, <1GB VRAM
- Coqui XTTS-v2 - non-commercial license (rejected)
- Bark (Suno) - 4GB, slower, lower quality than Kokoro
- F5-TTS - CC-BY-NC license (rejected)
- MeloTTS - Apache 2.0 but Kokoro beats it on quality
- Piper - CPU-only, weaker prosody

Winner: Kokoro-82M on quality-per-VRAM AND open license.

Pre-slice LocalTTS was a pyttsx3 wrapper - functionally identical to
SystemTTS (both wrap OS SAPI/say/espeak). Misleading name, no neural
component. Rewrite makes LocalTTS the true neural local path and keeps
SystemTTS as the explicit OS-builtin fallback, mirroring the
imagegen/threed/videogen pattern.

Changes:
- Rewrote LocalTTS to use kokoro.KPipeline with bf16-friendly defaults,
  9 canonical voices (af_/am_/bf_/bm_), .wav output via soundfile, optional
  sounddevice playback for speak(). Loud-fail on ImportError/Exception
  (logger.error + return False), no silent fallback to system.
- AudioGen.__init__ default_provider: "system" -> "local"
- argparse --provider default: "system" -> "local"
- Updated header docstring to name Kokoro-82M as the engine.
